# 08 面试题库与简历对齐：把项目变成"你的项目"

> 目标：30 秒能开场、3 分钟能讲全、被追问五层不慌；简历上的每个数字都能对上代码。
> 预计用时：D7 下午（约 4 小时，含录音复述）

---

## 1. 开场：三个版本，背到能条件反射

### 1.1 30 秒版（自我介绍里用）

> "我做过一个电商 ERP 的二次开发，上游是开源的进销存底座。
> 我在上面主要做三件事：把库存扣减重构成原子更新 + 流水 + 对账；
> 把订单/售后状态判断收敛成显式状态机；再给 AI Agent 加了一层工具网关，
> 做权限分级、审批、审计和租户隔离。技术栈是 Spring Boot 4 + MyBatis-Plus + MySQL + Redis + Spring AI。"

### 1.2 3 分钟版（项目深挖时用）

按"背景 → 问题 → 方案 → 结果 → 反思"讲：

1. **背景**（20 秒）：电商 ERP，多商户、多平台、进销存 + 售后；上游能跑，但写路径不可控。
2. **问题**（40 秒）：三个具体问题——库存先查后写会超卖；状态判断散落 if/else；AI 能直接调工具写库，没有刹车。
3. **方案**（60 秒）：
   - 库存：单一入口 `changeStock` + 条件原子 SQL + 同事务流水 + 唯一索引幂等 + 定时对账；
   - 状态：显式迁移表 + 校验器 + 事件审计；
   - Agent：自定义 `ToolCallback` 接入网关，八步流水线（策略/租户/幂等/锁/审批/执行/审计/指标）。
4. **结果**（30 秒）：50 线程并发不超卖；跨租户越权用例被拦；审批可闭环；RAG 评测 Recall@10 0.93。
5. **反思**（30 秒）：最大的坑不是写代码，是"链路断在五个地方"——审批例子。

### 1.3 一句话版本（被问"你最有成就感的是什么"）

> "把'AI 能写库'这件事从'能跑'做成'敢上线'——每一步都有权限、有审批、有审计、有回滚。"

## 2. 题库：35 题，按追问深度排序

> 用法：先自己答，再看"答题骨架"。骨架只给要点，具体表述要用自己的话。

### A. 项目与架构（8 题）

**A1. 介绍一下这个项目的整体架构。**
骨架：单体多模块（7 个）→ 依赖方向 → 分层（Controller/Service/Mapper）→ Agent 运行时单独包 →
数据层 MySQL/Redis/PG → 一句话说清"业务底座 + 智能体治理"两层。

**A2. 为什么用单体，不拆微服务？**
骨架：事务边界（订单/库存/采购同库）→ 团队规模（个人维护）→ 运维成本 →
用模块边界模拟隔离（service 不依赖 erp-api）→ 将来可拆的点（Agent 运行时）。

**A3. 模块是怎么划分的？依据是什么？**
骨架：按"变化频率 + 依赖方向"分。`model` 最稳定被所有层依赖；`service` 放业务；
`erp-api` 放接入与编排；`open-sdk` 隔离外部平台变化（防腐层）。

**A4. 一次带 JWT 的请求经过哪些组件？**
骨架：过滤器（认证）→ SecurityConfig（授权）→ TenantInterceptor（租户）→ Controller → Service → Mapper。
加分：指出 `permitAll` 会被过滤器短路，两者白名单要一致。

**A5. 为什么订单要两张表（oms_shop_order / o_order）？**
骨架：平台原始单保留快照（字段不可控、便于对账/重放）→ 内部单承载履约状态 →
转换层 `pushOms` 做字段映射与状态归一。

**A6. 如果让你重做，会怎么改？**
骨架：① 统一返回体（现在三套）；② 多租户用 MyBatis 插件而不是每个 Tool 手写；
③ 审计异步化 + 批量落库；④ 状态机用枚举 + 图而不是 int 常量；⑤ 前端类型生成。

**A7. 这个项目你觉得最脆弱的地方是哪？**
骨架：诚实说——"第三道租户过滤靠工具自觉"；"审计是同步单条插入"；
"补偿顺序不是严格逆拓扑"。每一条都给改进方向。

**A8. 你从上游继承了什么，自己做了什么？**
骨架：见第 4 节能力边界表，务必背熟。

### B. 并发与一致性（8 题）

**B1. 怎么防止超卖？**
骨架：条件原子更新 `UPDATE ... WHERE quantity >= ? AND available >= ?`；
不用"先查后写"；失败返回 0 由业务回滚；配合唯一索引幂等。

**B2. 乐观锁是怎么实现的？哪些情况会失效？**
骨架：`@Version` + `OptimisticLockerInnerInterceptor`；只对 `updateById` 且 version 非空生效；
原生 SQL / UpdateWrapper 不生效；所以库存用 SQL 里手写 `version+1`，并发控制靠条件更新而不是 version。

**B3. 分布式锁怎么用的？会不会死锁？**
骨架：Redisson `tryLock(0, ttl)`；可重入、释放校验持有者；
显式 leaseTime 关闭 watchdog → 长任务有提前释放风险；只锁单工具名，无环路。

**B4. 幂等怎么做？**
骨架：三层——Redis `SET NX`（processing/completed）、数据库唯一索引（最终裁决）、
状态机（重复取消被状态机拦）；失败删除 key 允许重试；Redis 挂 fail-open。

**B5. 事务在什么情况下会失效？**
骨架：自调用（this 调用，代理不生效）、非 public、异常被吞、rollbackFor 没配、
异步线程、多数据源。项目里 `TransitionValidator` 发事件用 `REQUIRES_NEW`，是"独立事务"的例子。

**B6. 库存对账怎么做的？**
骨架：五项校验（可用量、批次、账实、负库存/超锁、流水链）；
总库存是事实，只补流水/调批次，不改总库存；负库存和链断裂必须人工。

**B7. 状态机怎么保证不被绕过？**
骨架：所有写入口调 `TransitionValidator`；非法迁移抛异常；事件落 Trace；
诚实说：仍有人工/管理型通道 `recordAdministrativeRefundTransition`，只记录不拦截。

**B8. 你怎么验证并发安全？**
骨架：50 线程直连 MySQL 抢同一行；断言不超卖、不为负、流水条数一致；
强调"必须用真实 MySQL，H2 行锁语义不同"。

### C. Agent 运行时（7 题）

**C1. Spring AI 的 @Tool 是怎么执行的？为什么 AOP 拦不住？**
骨架：`MethodToolCallback` 反射 `method.invoke`；注解在原始方法上，代理被绕过；
解决：自定义 `ToolCallback` 装饰器，内部转调网关；`ToolDefinition` 仍由官方 Provider 生成。

**C2. 工具网关做了哪些事？顺序是什么？**
骨架：八步；重点解释"幂等必须在锁之前""审批必须在执行之前""finally 必须释放锁"。

**C3. 五级自治分别是什么语义？**
骨架：OBSERVE 只读 / SUGGEST 只出建议 / DRAFT 只建草稿单 / EXECUTE 直接写+审计 /
ESCALATE 必须审批；说明 SUGGEST 靠工具自律，DRAFT 靠网关强制。

**C4. 审批闭环怎么走？**
骨架：PENDING → APPROVED →（claimApproved 原子抢占）→ EXECUTED；
traceId 会话级稳定；参数摘要防调包；过期 5 分钟；失败回 PENDING。

**C5. 你怎么知道 Agent 做了什么？**
骨架：ActionLedger（谁/什么/入参/出参/耗时/结果/审批人）+ Trace（一次执行的节点链路）+
Metrics（聚合指标）；三者职责不同。

**C6. 多租户怎么隔离？**
骨架：登录态取租户（不信请求头）→ 网关 fail-closed → 查询条件；
承认第三道靠人工，改进方向是 MyBatis 多租户插件/行级权限。

**C7. 如果用户让 AI"把所有订单删了"，会发生什么？**
骨架：没有删订单工具（能力最小化）→ 有写工具也是 ESCALATE → 审批 + 参数摘要 →
即使批准也受状态机约束（已发货不能取消）→ 全程审计。
加分：提到 prompt injection——"工具描述和系统提示都可能被注入，最终防线是权限和审批，不是 prompt"。

### D. RAG（5 题）

**D1. 为什么用混合检索？**
骨架：向量擅长语义、BM25 擅长精确词；单路各有盲区；RRF 只融合排名，避免量纲问题。

**D2. RRF 公式是什么？为什么用 rank 不用分数？**
骨架：`Σ 1/(k+rank)`；不同检索器分数不可比；rank 是天然归一化；k 平滑头部。

**D3. 怎么评测 RAG？**
骨架：检索（Recall@K/MRR/NDCG）+ 生成（Relevancy/Correctness/Faithfulness/BLEU/ROUGE/LLM-judge）；
报真实数字；解释"Correctness 低说明瓶颈在生成"。

**D4. 怎么减少幻觉？**
骨架：强制引用 chunkId；Faithfulness 指标；prompt 限定"只根据资料回答"；
检索不到就说不知道（KnowledgeTools 空结果提示）；审批/权限兜底。

**D5. chunk 怎么切？**
骨架：按 SOP 文档的语义段切（标题 + 正文），不是固定长度硬切；
chunk 带 docId/title/merchantId；太大稀释相关性，太小丢上下文。

### E. Java / Spring / MySQL / Redis（7 题）

**E1. 项目里哪里用了 ConcurrentHashMap？为什么？**
骨架：`ToolGateway.executionLocks`（工具级互斥）、`PolicyRegistry.registry`（启动写、运行读）、
`MemoryManager.workingMemoryCache`；读多写少、需要线程安全、不用加锁。

**E2. ThreadLocal 在异步链路里会怎样？**
骨架：Reactor 线程切换导致丢值；`GatewayToolCallback` 在进入同步方法前显式 set、finally clear；
线程池复用必须清理，否则串租户。

**E3. 这条 SQL 走索引了吗？**
骨架：`WHERE id = ? AND is_delete = 0 AND quantity >= ?` —— 主键定位；
如果按 `merchant_id + create_time` 查，需要联合索引；用 EXPLAIN 看 type/rows/Extra。

**E4. MySQL 默认隔离级别？MVCC 怎么实现的？**
骨架：RR（可重复读）；undo log + read view；快照读 vs 当前读；
`UPDATE ... WHERE` 是当前读，所以能看到最新值并加锁。

**E5. Redis 缓存三大问题在项目里怎么体现？**
骨架：穿透（null 不缓存 → 可缓存空值）、击穿（热点 key 过期 → 互斥重建）、
雪崩（TTL 打散）；项目 `GoodsCacheService` 有热点商品缓存，`evictAllSearchCache` 用 KEYS 是待改点。

**E6. REQUIRES_NEW 有什么用？有什么坑？**
骨架：独立事务，外层回滚不影响内层；坑是占两个连接、内层失败不影响外层、
以及"校验通过但业务回滚，Trace 仍留成功记录"的一致性问题。

**E7. 你们 JVM 调过吗？**
骨架：诚实说"没有深度调优"；但知道项目 JDK 17 编译、21 运行；
关注点：堆/元空间、G1、Full GC 排查（jstat/jmap/arthas）；
把话题引回"我更关注数据库连接池和慢 SQL"。

## 3. 高频追问链（面试官会连问三层）

### 链一：超卖

```
问：怎么防超卖？
答：条件原子更新。
问：为什么不用乐观锁？
答：乐观锁要重试，高并发下重试成本高；条件更新一次成功或失败，更适合库存。
问：那 version 还有什么用？
答：变更序号，给增量同步/排查用；并发控制不依赖它。
问：如果分库分表了呢？
答：单行原子性不够，要分段库存/预扣/最终一致，或者用 Redis 预扣 + 异步落库。
```

### 链二：审批

```
问：审批怎么实现的？
答：网关拦截 ESCALATE → 建审批单 → 人工批准 → 重发命中 → 执行。
问：怎么保证批准的是同一件事？
答：参数摘要（JSON 序列化后全等比对）。
问：用户改了参数再发呢？
答：摘要不匹配，拒绝，要求重新审批。
问：两个人同时点批准？
答：claimApproved 条件更新 APPROVED→EXECUTED，只有一个 affected=1。
```

### 链三：RAG

```
问：为什么向量检索不够？
答：专有名词/编号类查询向量弱，BM25 强；语义改写 BM25 弱，向量强。
问：怎么融合？
答：RRF，只用排名。
问：怎么证明融合比单路好？
答：同一评测集跑三组（向量/BM25/混合），比 Recall@10 和 MRR。
问：现在瓶颈在哪？
答：Correctness 0.79 < Recall 0.93，瓶颈在生成，不在检索。
```

### 4.4 如果被问"这是不是 AI 写的"

不要慌，也不要否认。标准答法：

> "上游是开源项目，我的二次开发里确实大量用了 AI 辅助生成初版代码。
> 但 AI 生成的部分我做了三件事：逐行 review、补测试、修它留下的坑。
> 比如审批闭环那个 bug，就是 AI 把 traceId 写成每次随机，导致批准后永远匹配不上——
> 这类问题不跑一遍是发现不了的。所以我更愿意说我是'用 AI 写，但按工程标准验收'。"

这个回答同时展示了：诚实、review 能力、测试意识、真实踩坑。

## 7. 写在最后

你不需要"读懂全部代码"才能面试。你需要的是：

1. **一条能讲通的主线**（业务 → 一致性 → 智能体）；
2. **两个能讲深的技术点**（库存原子更新、工具网关）；
3. **三个能讲真的事故**（审批五连断、PgVector 饿汉、锁误删）；
4. **一份对得上代码的简历**。

剩下的，交给表达。

> 面试不是考试，是"让对方相信你能干活"。
> 你能把"我怎么发现一个问题、怎么修、怎么证明修好了"讲清楚，
> 就已经超过大多数只会背八股的候选人。

## 附：与 PaiAgent 的衔接（下一阶段预告）

启航讲完后，PaiAgent 的学习重点会完全不同：

| 维度 | 启航 | PaiAgent |
|------|------|----------|
| 定位 | 业务底座 + 自研运行时 | 工作流编排平台 |
| 编排 | 自研 DAG | LangGraph4j 状态图 |
| 重点 | 一致性、权限、审计 | 图编排、条件边、HITL、双引擎对比 |
| 面试叙事 | "我把 AI 关进笼子" | "我理解了 Agent 的执行模型" |

两项目不要讲成"两个 CRUD"，要讲成**互补**：
一个证明你能做工程治理，一个证明你懂 Agent 原理。
