一、系统分层架构

从平台接入到业务中台、履约、库存、AI 与数据基础设施，形成一套可对接外部 ERP/WMS/财务系统的基础底座。

访问与角色入口

  • Vue 3 管理端、首页驾驶舱、帮助中心
  • 供应商门户：产品、报价、备货、库存、客户
  • OpenAPI、OAuth 回调、SSE 浏览器消息
  • 飞书/钉钉/企微 Webhook 外部通知

应用与接口层

  • ERP 核心控制器：商品、订单、采购、售后、库存
  • OMS 平台控制器：店铺、商品、订单、退款、面单
  • 开放 API：商品/SKU 等外部系统对接
  • AI 控制器：聊天、简报、分析、模型配置

核心业务域

  • 商品主数据、店铺商品映射、SKU 绑定
  • 订单聚合、审核、发货、售后处理
  • 采购订单、供应商、报价、入库
  • 仓库、库位、批次、出入库、库存预警

平台与外部系统

  • 淘宝、京东、拼多多、抖店、微信小店等平台
  • 物流公司、电子面单、三方云仓
  • 供应商代发、第三方 ERP/WMS/OMS
  • OpenAI 兼容模型、向量与 RAG 能力

数据与运行基础设施

  • MySQL 8：交易、主数据、配置、日志
  • Redis：缓存、任务与运行态支撑
  • 文件/图片存储与静态资源服务
  • SSE、定时任务、消息推送、调用日志

四、关键业务流程拆解

下面五条流程最能体现系统内部的数据流转与跨模块协同。

平台初始化

  1. 维护店铺及商户归属，启用对应电商平台。
  2. 跳转平台 OAuth 或录入 AppKey，保存 AccessToken/会话凭证。
  3. 定时任务拉取店铺商品与订单。
  4. 在拉取日志中检查成功、失败和重试情况。
  5. 完成 ERP SKU 与店铺 SKU 绑定后进入日常业务。

订单到发货

  1. 订单库/店铺订单聚合平台订单，或手工创建内销订单。
  2. 审核订单并自动或手动关联 ERP SKU。
  3. 在发货中心选择手工、电子面单、供应商或云仓履约。
  4. 仓库生成备货/出库单，扫码或人工完成出库。
  5. 回填运单和物流轨迹，将发货状态回传平台。

采购到入库

  1. 基于补货需求创建采购订单，选择供应商和采购明细。
  2. 供应商报价/审核规则辅助选品与定价。
  3. 供应商发货并录入采购物流。
  4. 收货确认后生成采购入库单。
  5. 入库增加库存，形成批次、库位、价格与库存流水。

售后闭环

  1. 平台售后列表/详情拉取到店铺售后。
  2. 售后单推送到 OMS 售后中心并聚合到订单售后库。
  3. 根据业务选择退货、换货或补发处理。
  4. 录入退回物流、收件信息或补发发货信息。
  5. 更新处理结果和售后台账，并按需回传平台/第三方。

AI 分析、消息与外部通知

  1. 模型配置提供 OpenAI 兼容的地址、Key、模型和默认配置。
  2. AI 助手或专题分析按问题调用订单、库存、售后等业务工具。
  3. 结果通过 SSE 流式返回，并写入分析历史记录。
  4. 定时监控发现销售、库存、发货或退款异常。
  5. 消息写入系统通知表，经 SSE 展示，并按等级推送到飞书/钉钉/企微。
